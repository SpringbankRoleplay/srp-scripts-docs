## Installation

<Steps>
  <Step title="Download the resource">
    Grab the latest release from GitHub and extract it into `resources/[srp]/`.
  </Step>

  <Step title="Add it to server.cfg">
    srp-core starts **after** the resources it bridges to (so it can detect
    them) and **before** any resource that uses it.

    ```cfg
    ensure ox_lib
    ensure ox_target
    ensure ox_inventory     # your inventory, phone and notify resources

    ensure srp-core

    ensure srp-reports      # our resources
    ```
  </Step>

  <Step title="Restart">
    Check the console on startup. For every module without a convar, srp-core
    prints the bridge it detected:

    ```
    [srp-core] [INFO] module "inventory": detected bridge "ox"
    ```
  </Step>
</Steps>

## Configuration

Bridges, language and identifier are configured through convars in
`server.cfg`. You should not need to edit any file inside the resource, except
the rank list (see [Staff ranks](#staff-ranks)).

### Convars

<Properties>
  <Property name="srp-core.bridge.target" type="string" defaultValue="auto">
    Targeting bridge. Accepts `ox`.
  </Property>

  <Property name="srp-core.bridge.notify" type="string" defaultValue="auto">
    Notification bridge. Accepts `okok` (okokNotify), `mythic` (mythic_notify),
    `ox` or `esx`.
  </Property>

  <Property name="srp-core.bridge.inventory" type="string" defaultValue="auto">
    Inventory bridge. Accepts `ox` (ox_inventory), `qs` (qs-inventory), `codem`
    (codem-inventory) or `esx` (ESX default inventory).
  </Property>

  <Property name="srp-core.bridge.phone" type="string" defaultValue="auto">
    Phone bridge. Accepts `lb` (lb-phone), `qs` (qs-smartphone) or `npwd`.
  </Property>

  <Property name="srp-core:locale" type="string" defaultValue="'nl'">
    Language every SRP resource uses for its texts. Missing keys fall back to
    English. See [sCore.locale](/srp-core/import/shared/#scorelocale).
  </Property>

  <Property name="srp-core:mainIdentifier" type="string" defaultValue="'license'">
    Identifier type used as the player key (`license`, `steam`, `discord`,
    `fivem`, ...). See [sCore.identifier](/srp-core/import/server/#scoreidentifier).
  </Property>
</Properties>

```bash
setr srp-core.bridge.notify "okok"
setr srp-core.bridge.inventory "ox"
setr srp-core:locale "nl"
set  srp-core:mainIdentifier "license"
```

<Callout type="warning">
  Use `setr` for the bridge and locale convars. They are read on both the
  client and the server, and a plain `set` convar is invisible to the client:
  the client would silently use another bridge or language than the server.
  `srp-core:mainIdentifier` is only read on the server, so `set` is enough.
</Callout>

<Callout type="info">
  An unknown bridge value logs an error on startup, but does not stop the
  resource: srp-core falls back to the detected bridge, or the default when
  nothing is detected. Check the console if a bridge does not behave as
  configured.
</Callout>

### Auto-detection

Leave a bridge convar out and srp-core picks the first supported resource that
is running, in this order:

| Module | Detection order | Default when nothing is found |
|---|---|---|
| `notify` | okokNotify → mythic_notify → ox_lib → es_extended | `ox` |
| `inventory` | ox_inventory → qs-inventory → codem-inventory → es_extended | `ox` |
| `phone` | lb-phone → qs-smartphone → npwd | none (phone calls are skipped with a warning) |
| `target` | ox_target | `ox` |

Set the convar only when you want something other than the detected bridge,
for example `ox` notifications on a server that also runs okokNotify.

<Callout type="warning">
  Detection only sees resources that are already running. Start srp-core
  **after** your inventory, phone and notify resources.
</Callout>

### Staff ranks

Ranks are granted through ACE: `srp.rank.<rank>`. A higher rank counts as every
rank below it.

```bash
add_ace group.mod   srp.rank.mod   allow
add_ace group.admin srp.rank.admin allow
add_principal identifier.license:abc123 group.admin
```

The default ranks, lowest first, are `jrmod`, `mod`, `srmod`, `admin` and
`owner`. To use other names, change `Config.ranks` in `src/config/config.lua`,
and keep a copy because updates overwrite it. See
[sCore.ranks](/srp-core/import/server/#scoreranks).

### Debugging

The detected bridges are always printed on startup. To also see which modules
each Lua resource loads, turn on debug output for that resource:

```bash
setr srp-core:debug.srp-garage true
```

```
[srp-garage] [core] [DEBUG] loaded module "notify" (client)
```

See [Debug gating](/srp-core/import/integrated/#debug-gating) for narrowing this
down further.

<Callout type="warning">
  `Config.bridgeSettings` in `config.lua` declares which bridges exist. Editing
  it is not a supported way to configure your server, and your changes will be
  overwritten on update. Use the convars above.
</Callout>
