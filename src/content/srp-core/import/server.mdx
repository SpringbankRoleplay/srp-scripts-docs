# Server

## sCore.notify <Badge variant="server">server</Badge>

Sends a notification to one player, several players or everyone. It uses the
same fields as the [client version](/srp-core/import/client/#scorenotify).

```lua
sCore.notify(source, { title = 'Shop', description = 'Purchase complete', type = 'success' })
sCore.notify({ 1, 4, 7 }, { description = 'Shop is closing.' })
sCore.notify(-1, { description = 'Restart in 5 minutes.' })
```

```js
sCore.notify(source, { title: 'Shop', description: 'Purchase complete', type: 'success' });
```

## sCore.inventory <Badge variant="server">server</Badge>

One item API for every supported inventory. The functions are the same for
every bridge, so your resource never needs to know which inventory the server
runs.

```lua
if sCore.inventory.canCarryItem(source, 'water', 2) then
    sCore.inventory.addItem(source, 'water', 2)
end

if sCore.inventory.removeItem(source, 'lockpick', 1) then
    -- ...
end
```

<Properties>
  <Property name="getItemCount(source, item)" type="function">Returns a number.</Property>
  <Property name="hasItem(source, item, count?)" type="function">`true` when the player has at least `count` (default 1).</Property>
  <Property name="addItem(source, item, count, metadata?)" type="function">Returns `true` on success.</Property>
  <Property name="removeItem(source, item, count, metadata?)" type="function">Returns `true` on success.</Property>
  <Property name="canCarryItem(source, item, count)" type="function">Weight and slot check.</Property>
  <Property name="getItemLabel(item)" type="function">Display name, or `nil`.</Property>
  <Property name="registerUsableItem(item, cb)" type="function">
    `cb(source, item)` runs when a player uses the item.
  </Property>
</Properties>

### Bridge support

| Function | ox | qs | codem | esx |
|---|---|---|---|---|
| getItemCount / hasItem | ✓ | ✓ | ✓ | ✓ |
| addItem / removeItem | ✓ | ✓ | ✓ | ✓ |
| metadata | ✓ | ✓ | add only | ✗ |
| canCarryItem | ✓ | ✓ | ✗ | ✓ |
| getItemLabel | ✓ | ✓ | ✓ | ✓ |
| registerUsableItem | ✓ (see below) | ✓ | ✗ | ✓ |

An unsupported function logs a warning and returns `nil`.

<Callout type="warning" title="Usable items with ox_inventory">
  ox_inventory only runs code for items that point to an export. Add this to the
  item in `ox_inventory/data/items.lua`:

  ```lua
  ['bandage'] = {
      label = 'Bandage',
      server = { export = 'your-resource.bandage' },
  },
  ```

  `registerUsableItem('bandage', cb)` creates that export in your resource.
  Return `false` from `cb` to cancel the use.
</Callout>

<Callout type="info">
  qs-inventory, codem-inventory and older ESX versions don't document what
  `addItem`/`removeItem` return. For those bridges srp-core only reports failure
  when the inventory explicitly returns `false`.
</Callout>

## sCore.phone <Badge variant="server">server</Badge>

Messages, mail and notifications to a player's phone.

```lua
local number = sCore.phone.getPhoneNumber(source)

sCore.phone.sendMessage(source, 'Mechanic', 'Your car is ready.')

sCore.phone.sendMail(source, {
    sender  = 'city@hall.gov',
    subject = 'Permit approved',
    message = 'Your business permit has been approved.',
})

sCore.phone.sendNotification(source, {
    app         = 'Mail',
    title       = 'Garage',
    description = 'Vehicle stored',
})
```

<Properties>
  <Property name="getPhoneNumber(source)" type="function">The player's number, or `nil`.</Property>
  <Property name="sendMessage(source, sender, message)" type="function">
    SMS from `sender` (a number or name).
  </Property>
  <Property name="sendMail(source, { sender?, subject, message })" type="function">E-mail to the player.</Property>
  <Property name="sendNotification(source, { app?, title, description })" type="function">
    Push notification on the phone.
  </Property>
</Properties>

### Bridge support

| Function | lb | qs | npwd |
|---|---|---|---|
| getPhoneNumber | ✓ | ✓ | ✓ |
| sendMessage | ✓ | ✓ (shown as app message) | ✓ |
| sendMail | ✓ | ✓ (no `sender`) | ✗ |
| sendNotification | ✓ (`app` required) | ✓ | ✗ |

<Callout type="warning">
  lb-phone needs `app` in `sendNotification`: the identifier of an app that
  exists on the phone, such as `"Mail"`. Without it nothing is sent.
</Callout>

## sCore.identifier <Badge variant="server">server</Badge>

One identifier type for every SRP resource, so player data lines up across
scripts.

```lua
local id = sCore.identifier.get(source)               --> "license:abc123" or nil
local discord = sCore.identifier.get(source, 'discord') --> "discord:1234" or nil
```

<Properties>
  <Property name="sCore.identifier.get(source, type?)" type="function">
    The player's identifier of `type`, or of the main type when omitted.
    Returns `nil` when the player has none.
  </Property>
  <Property name="sCore.identifier.mainType()" type="function">
    The configured main type, e.g. `"license"`.
  </Property>
</Properties>

```bash
set srp-core:mainIdentifier "license"
```

## sCore.ranks <Badge variant="server">server</Badge>

Staff ranks without an admin framework. Ranks are listed lowest first in
srp-core's config and granted through ACE.

```lua
Config.ranks = { 'jrmod', 'mod', 'srmod', 'admin', 'owner' }
```

Give a group a rank in `server.cfg`:

```bash
add_ace group.admin srp.rank.admin allow
add_ace group.mod   srp.rank.mod   allow
add_principal identifier.license:abc123 group.admin
```

```lua
if sCore.ranks.has(source, 'jrmod') then
    -- jrmod, mod, srmod, admin and owner all pass
end

local rank = sCore.ranks.get(source) --> "admin" or nil
```

<Properties>
  <Property name="sCore.ranks.has(source, rank)" type="function">
    `true` when the player has `rank` or any rank above it.
  </Property>
  <Property name="sCore.ranks.get(source)" type="function">
    The player's highest rank, or `nil`.
  </Property>
</Properties>

<Callout type="warning">
  An unknown rank name logs a warning and returns `false`. Check the spelling
  against `Config.ranks`.
</Callout>
