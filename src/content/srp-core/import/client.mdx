# Client

## sCore.notify <Badge variant="client">client</Badge>

Shows a notification through the configured notify bridge
(`srp-core.bridge.notify`).

```lua
sCore.notify({
    title       = 'Garage',
    description = 'Vehicle stored',
    type        = 'success',
})
```

<Properties>
  <Property name="title" type="string">Heading of the notification.</Property>
  <Property name="description" type="string">Body text.</Property>
  <Property name="type" type="string" defaultValue="'info'">
    `success`, `error`, `inform`/`info` or `warning`. Each bridge maps these to
    its own types; mythic_notify has no warning style and shows it as `inform`.
  </Property>
  <Property name="duration" type="number" defaultValue="5000">Milliseconds.</Property>
  <Property name="position" type="string" defaultValue="'top-right'">
    `top`, `top-right`, `top-left`, `bottom`, `bottom-right`, `bottom-left`,
    `center-right`, `center-left`.
  </Property>
  <Property name="icon" type="string">Icon name (ox bridge only).</Property>
</Properties>

<Callout type="info">
  mythic_notify shows a single line: `title: description`.
</Callout>

## sCore.framework <Badge variant="client">client</Badge>

The local player's job and framework events. Same job format and `jobs` rules
as [the server version](/srp-core/import/server/#scoreframework-server).

```lua
local job = sCore.framework.getJob()

if sCore.framework.hasJob({ police = true }) then
    -- ...
end

sCore.framework.onJobUpdate(function(job, lastJob)
    print(('job changed to %s'):format(job and job.name or 'none'))
end)
```

<Properties>
  <Property name="getJob()" type="function">`{ name, label, grade, gradeLabel, onDuty }` or `nil`.</Property>
  <Property name="hasJob(jobs)" type="function">`true` when the job matches `jobs`.</Property>
  <Property name="matches(job, jobs)" type="function">Same check for a job table you already have.</Property>
  <Property name="onPlayerLoaded(cb)" type="function">`cb()` when the player has loaded in.</Property>
  <Property name="onPlayerUnloaded(cb)" type="function">`cb()` when the player logs out (character switch).</Property>
  <Property name="onJobUpdate(cb)" type="function">`cb(job, lastJob)` when the job changes.</Property>
</Properties>

### Events

These are local client events, so every resource on the client can listen:

| Event | Arguments | ESX | Qbox |
|---|---|---|---|
| `srp-core:framework:onPlayerLoaded` | none | `esx:playerLoaded` | `QBCore:Client:OnPlayerLoaded` |
| `srp-core:framework:onPlayerUnloaded` | none | `esx:onPlayerLogout` | `QBCore:Client:OnPlayerUnload` |
| `srp-core:framework:onJobUpdate` | `job, lastJob` | `esx:setJob` | `QBCore:Client:OnJobUpdate` |

Qbox doesn't send the previous job, so srp-core keeps track of it and `lastJob`
works on both frameworks.

<Callout type="info">
  `getJob` asks the framework every time it is called. In code that runs every
  frame (for example a target's `canInteract`), keep your own copy and update it
  with `onJobUpdate`.
</Callout>

## sCore.inventory <Badge variant="client">client</Badge>

Read-only item checks for the local player. Changing items is server-only, see
[sCore.inventory on the server](/srp-core/import/server/#scoreinventory-server).

```lua
if sCore.inventory.hasItem('lockpick') then
    -- ...
end

local water = sCore.inventory.getItemCount('water')
```

<Properties>
  <Property name="getItemCount(item)" type="function">
    How many of `item` the player has.
  </Property>
  <Property name="hasItem(item, count?)" type="function">
    `true` when the player has at least `count` (default 1).
  </Property>
</Properties>

<Callout type="warning">
  codem-inventory has no documented client export for item counts. With the
  `codem` bridge both functions log a warning and return `nil`/`false`. Check
  items on the server instead.
</Callout>

## sCore.target <Badge variant="client">client</Badge>

Targeting through the configured target bridge (`srp-core.bridge.target`). The
functions take the same arguments as their
[ox_target](https://coxdocs.dev/ox_target) counterparts.

```lua
local zone = sCore.target.addBoxZone({
    coords = vec3(441.0, -981.0, 30.7),
    size = vec3(2, 2, 2),
    options = {
        { label = 'Open', onSelect = function() end },
    },
})

sCore.target.removeZone(zone)
```

<Properties>
  <Property name="Zones" type="function">
    `addBoxZone`, `addSphereZone`, `addPolyZone` (return the zone id), `removeZone`
  </Property>
  <Property name="Entities" type="function">
    `addEntity`, `removeEntity`, `addLocalEntity`, `removeLocalEntity`, `addModel`, `removeModel`
  </Property>
  <Property name="Globals" type="function">
    `addGlobalOption`, `addGlobalObject`, `addGlobalPed`, `addGlobalPlayer`,
    `addGlobalVehicle` and their `remove*` versions
  </Property>
  <Property name="disableTargeting" type="function">
    `disableTargeting(state)`
  </Property>
</Properties>

<Callout type="info">
  Zones and options belong to your resource, so they are removed when your
  resource stops, not when srp-core does.
</Callout>
